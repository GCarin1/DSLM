# DSLM 1.0.0 — a tiny LLM on your Nintendo DS

DSLM runs a small Llama 2 language model **entirely offline** on an original Nintendo DS or DS Lite, launched from an R4 flashcart. Type the start of a story on the touch screen and watch the DS write the rest, token by token. No network, no PC: the model travels on the microSD card.

## Download and install

1. Download **`dslm-v1.0.0.zip`** below.
2. Unzip it at the **root** of your flashcart's microSD card (the kernel must already be installed). You should see `dslm.nds` and a `dslm` folder.
3. Launch `dslm.nds` from your kernel's menu.

Full instructions, controls and troubleshooting are in `README-DSLM.txt` inside the zip.

## What's New

- **Runs on real hardware, fast**: 6.55 tokens/s on a DS with an R4 clone, about 4x the floating-point build.
- **A real interface**: touch keyboard, live word-by-word streaming, stop at any time, story screen with scrolling, and a settings screen.
- **Buttons or stylus**: every action works both ways; L/R pick an example prompt if your stylus is lost.
- **Settings on the DS**: temperature, top-p, story length and **the model**, saved to the card. Drop another `llama2.c` checkpoint in `/dslm/models/` and pick it on the Settings screen; the DS reloads it without a restart and falls back to the previous model if the new one does not fit.
- **Offline by design**: the model (`stories260K`, MIT) is inside the package.

## Changes and defaults

- Default model: **`stories260K_q80.bin`** (int8, 522 KB, fixed-point engine). The fp32 `stories260K.bin` is included as a slower, exact reference; switch on the Settings screen (row `Model`) or with `checkpoint =` in `/dslm/dslm.ini`.
- Default settings: temperature 0 (the same prompt gives the same story), top-p 0.9, 256 steps. Change them on the Settings screen (SELECT).
- After every story the DS writes `/dslm/tokens.txt` and appends a line block to `/dslm/bench.txt` (timings, tokens/s, memory). Both are safe to delete.

## Bug Fixes

- Button presses right after a screen change are no longer lost.
- Text wraps at word boundaries instead of splitting words across lines.
- The title bar no longer runs the model name into the status.

## Technical

- **Engine**: port of Karpathy's `llama2.c`. The int8 path is integer-only after load (Q16 activations, Q30 weight scales, int64 accumulation, integer exp/sin/cos/sqrt with generated tables, no libm); the matmul runs from ITCM in ARM mode. A check on the linked binary proves that no soft-float routine is reachable from the per-token path.
- **Correctness**: the fp32 build matches `run.c` token for token (153/153 on hardware). The int8 build matches its own PC build bit for bit (257/257 on hardware) and follows `runq.c` for at least 64 generated tokens on every test prompt (measured 82 to 128).
- **Memory**: the int8 model uses about 1.4 MB of the DS's 4 MB (heap peak measured on melonDS); the loader checks the budget before allocating.
- **Formats**: fp32 checkpoints in the legacy `llama2.c` layout; int8 checkpoints in the `llama2.c` v2 layout (`ak42`, group size 4).
- **Toolchain**: BlocksDS (pinned Docker digest), DLDI on the ARM9; tested on melonDS 1.1 and on an R4 clone with YSMenu.
- **Not included**: flashcart kernels, firmware or DLDI drivers (get them from your cart's guide).

| Build | Load | Time per token | Tokens/s |
|---|---|---|---|
| int8 fixed point (default) | 124 ms | 152.7 ms | 6.55 |
| fp32 reference | 249 ms | 627.5 ms | 1.59 |

Measured on a Nintendo DS with an R4 clone (YSMenu), DS hardware timers, `emulated=no`.
